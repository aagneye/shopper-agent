# NearShelf Seller Agents Implementation Plan (Phase 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the seller side of NearShelf: a reusable shop kit, five generated shop sites (3 pharmacies, 2 parts dealers) and the Vayu parts catalogue.
- Each shop answers stock questions from a live, billing-fed API.
- Each shop shares a stock read with any agent site, takes holds in its own window, and refers to a partner shop.
- `npm run dev` runs the whole Neem Chowk demo locally.

**Architecture:**
- **Shop API.** A small, runtime-agnostic API (`shop-kit/api`) keeps each shop's stock, holds, sales and missed demand. It runs behind a local Node server now, and becomes Cloudflare Functions in Phase 3.
- **Shop sites.** Every shop site comes from one template (`shop-kit/template`) plus a profile and a billing CSV. A shop's page, its counter, its dashboard, its website tools and its bridge all reach the same API over same-origin `fetch`.
- **Parts catalogue.** A static site whose look-up reads a bundled catalogue.

**Tech Stack:** HTML, CSS, ES modules, Node 22 (`node:test`, `node:http`), the vendored toolkit. No npm dependencies.

**Spec:** `docs/idea.md`. Architecture and contracts: `docs/superpowers/plans/2026-11-20-nearshelf-architecture.md` §3.2–§4 and §7. The Phase 1 site is `sites/nearshelf`, whose partner URLs fix the shop origins.

## Global Constraints

Everything in the architecture plan's Global Constraints applies. In addition:

- **`shop-kit/api/*`:**
  - It uses no Node built-ins, so it can later run in Cloudflare Workers.
  - Every handler is `async` and returns `{status, body}`.
  - Storage goes through `{get(), set(state)}`.
- **Bands:** `qty - held` gives `available`. 0 means `out_of_stock`, 1–3 means `limited`, and more than 3 means `in_stock`.
- **Holds:**
  - The code is `H-` plus 4 digits, unique per shop.
  - A hold takes 1–5 units and never more than `available`.
  - Schedule `X` is never held. Schedules `H` and `H1` hold as `prescription`.
  - A hold lasts until the shop closes today, or 2 hours for a shop open 24 hours.
  - The name must be 2–60 characters and the phone 10 digits (an optional `+91` or leading `0` is allowed).
- **Shopper data:** names and phones are never returned to agents. The dashboard shows only the first name and `••••••` plus the last 2 digits. Missed-demand entries hold the query text only.
- **Origins:** shop origins and network names come from `sites/nearshelf/directory/neem-chowk.json`.
  - Reads (`check_stock`, `get_shop_info`, `lookup_part`) are shared with `callerOrigins: ["*"]`.
  - The `request_hold` write is shared only with NearShelf (`http://127.0.0.1:8080`) and the other area shops.
- **Referral partners:**
  - shanti_medical → night_owl_pharmacy
  - night_owl_pharmacy → shanti_medical
  - jeevan_chemist → night_owl_pharmacy
  - bharat_auto_spares → speedline_moto_parts
  - speedline_moto_parts → bharat_auto_spares
- **Shop reply contract** (architecture §3.3). The first line of a stock answer is:
  `AVAILABILITY: in_stock|limited|out_of_stock · ITEM: <…> · PRICE: <₹…> · STOCK AS OF: <time> · HOLD: yes|no|prescription`
- **Generated files:** `sites/<shop>/` is generated by `node shop-kit/generate.mjs <shop>`. Edit the template or the profile, never the output.

## Review Focus

1. **Overselling.** A sale or hold must never push `available` below 0, and a sale that would eat into held units is refused. Test in `shop-api.test.mjs`.
2. **Prescription and controlled items.** Schedule X gives `hold: "no"`, and a hold request is refused with a reason. H and H1 give `"prescription"`. Test in `shop-api.test.mjs`.
3. **Shopper details.** No API result an agent can get, and no bridge result, contains the name or phone. The dashboard list masks them. Test in `shop-api.test.mjs`, plus the shop site tests.
4. **Loose shopper wording.** "children's paracetamol syrup" finds the paediatric suspension, and part numbers match exactly in any case. An empty query is refused, and junk is logged as missed. Test in `stock.test.mjs`.
5. **Stock changing between a read and a hold.** A hold made after the stock fell to 0 is refused with `ok: false`, never stored. Test in `shop-api.test.mjs`.

### Task 2: Shop API

**Files:**
- Create: `shop-kit/api/shop-api.mjs`, `shop-kit/api/memory-store.mjs`
- Test: `shop-kit/tests/shop-api.test.mjs`

**Interfaces:**
- Consumes:
  - Task 1.
  - `areaNow` and `formatMinutes` from `sites/nearshelf/js/clock.js`.
  - `openState` from `sites/nearshelf/js/directory.js`.
- Produces:
  - `createShopApi({profile, items, store, clock, allowReset}) -> {handle(request) -> Promise<{status, body}>}`, where a request is `{method, path, query, body}`.
  - `class MemoryStore {constructor(state); get(); set(state)}`
  - `initialState(items) -> {version: 1, items, holds: [], sales: [], missed: []}`
- Routes:

| Route | Body | Returns |
|---|---|---|
| `GET /api/stock?q=` | — | `{ok, query, asOf, matches: [{id, name, detail, price, availability, hold, match}]}`. Logs a miss when no full match is available. |
| `GET /api/stock/all` | — | `{ok, asOf, items: [{id, name, detail, price, qty, held, available}]}` |
| `POST /api/sale` | `{itemId, qty}` | `{ok, item}` or `{ok: false, reason}` |
| `POST /api/holds` | `{itemId, qty, name, phone}` | `{ok, code, until, summary, prescription}` or `{ok: false, field, reason}` |
| `GET /api/holds` | — | `{ok, holds: [{code, item, qty, name: firstName, phone: masked, until, at}]}` |
| `GET /api/missed` | — | `{ok, missed: [{query, count, last, reason}]}`, most-asked first |
| `POST /api/reset` | — | 403 unless `allowReset` |

  Anything else gets 404. A wrong method gets 405. A bad body gets 400.
